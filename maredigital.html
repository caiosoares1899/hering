01
Visão geral

O que é o Maré Digital

Kanban ágil single-file que roda no browser. Deploy = git push no GitHub Pages.

📄
Single-file app
HTML, CSS e JS num único arquivo por tela, com <script type="module"> importando o SDK do Firebase direto do CDN. Sem build, sem npm no root, sem servidor próprio.
🔄
Tempo real
Firebase Realtime DB via WebSocket — qualquer mudança aparece no board de todos em menos de 1s. Cards, presença, notificações e comentários são todos listeners ao vivo.
🤖
Agente Ágil
Orquestrador de IA rodando em Cloud Function: lê o card, o board inteiro e a base de conhecimento ágil, e age via ferramentas (mover, comentar, editar campos, perguntar a um humano).
🔔
Push de verdade
Notificações in-app viram push (Firebase Cloud Messaging) quando o tipo está na allow-list — respeitando a janela de "Não Perturbe" de cada pessoa.
🏢
Multi-squad
Um deployment serve N squads via ?squad=id, incluindo squads criados dinamicamente pelo Painel. Dados isolados por squad no Firebase.
🔒
Acesso controlado no servidor
Login Google restrito a @ciahering.com.br (+ uma whitelist de externos por squad). Associação usuário↔squad validada nas próprias Firebase Rules, não só na UI.
02
Infraestrutura

Arquitetura

GitHub Pages para as páginas, Firebase para dados e auth, Cloud Functions para tudo que precisa de um segredo ou rodar sem o browser aberto.

📦
O que fica no Firebase
Cards, tags, colunas, sprint cfg, automações, backups, comentários, notas, notificações, logs de erro, presença. Segregado por squad — regras validam associação usuário↔squad no servidor.
🔑
O que fica na Cloud Function
A chave da Anthropic, gerenciada via firebase functions:secrets:set (Secret Manager), nunca em HTML/localStorage. Além do push e do orquestrador, há Cloud Functions pra intake anônimo, backup semanal automático e a integração com Spotify (hoje pausada) — ver seção "Cloud Functions & Secrets".

Board & Visualizações

Três modos de visualização, filtros multicritério, drag-and-drop mouse e toque.

FunçãoO que faz
renderNormal()Grid de colunas. Cards ordenados por prioridade (critical→high→medium→low). Colunas minimizáveis.
renderRaiaOwner()"Raia · pessoa" — faixa horizontal por responsável. Sem dono = faixa de aviso pulsante no fim.
renderRaiaTag()"Raia · tipo" — faixa por tag. Cor da faixa = cor da tag. Sem tag = "Sem tipo".
toggleRaia()Cicla: Off → Raia pessoa → Raia tipo → Off. Rótulo do botão muda para indicar o modo.
passesFilter()Dono, tag, prazo (atrasado/hoje/7 dias), prioridade, impedido, com riscos — AND entre filtros.
handleDrag*()Drag-and-drop desktop com ghost-line indicando posição. Drop aciona Firebase + automações.
addTouchDnD()Touch DnD mobile via touchstart/move/end. Clone visual segue o dedo; detecta coluna via elementFromPoint().
openSearch() (Ctrl+K)Busca por texto em título, descrição e PO. Navegação por teclado (↑↓ Enter). Mostra os primeiros resultados em dropdown, mais um botão "Ver N cards no board" que aplica o texto como filtro persistente (#f-texto) e mostra todos os matches direto no board.
pedirCard() / liberarCardAgora()Card aberto por outra pessoa fica em modo somente-leitura com heartbeat de presença. Quem quer editar pode "Pedir o card" — dono recebe um aviso e, ao soltar (ou após o prazo de graça), quem pediu herda o lock automaticamente e o modal se atualiza sozinho.

7 dias sem edição: desbotado. 14 dias: emoji 💤 + mais transparente. Sinal visual de estagnação.
🔗
Dependências
Cards vinculados via "depende de". Mini-mapa de dependências no card. Modal com árvore completa.
💬
Comentários
Thread por card com @menção a membros, @card e @Agente Ágil. Persiste fora do card, em squads/{id}/card_comments/{cid}.
📊

WIP, throughput, cycle/lead time e bloqueios exibidos em tempo real — a mesma visão que a ferramenta visao_board do Agente Ágil consulta.

Supercards & Ficha Técnica

Um card pai com N cards filhos, com dados técnicos compartilhados entre eles.

🧩
Cards filhos
Um card pai (childCardIds) agrupa filhos (superParentId) — útil pra desdobrar uma campanha/entrega grande em partes menores sem perder o vínculo com o todo. Ao criar um filho, dá pra buscar entre cards já existentes no board (2+ caracteres) em vez de sempre criar um novo.
📄
Ficha Técnica compartilhada
Campos técnicos definidos no pai se propagam para os filhos. Título automático do filho reflete os objetivos ainda não marcados na Ficha Técnica — mas some assim que o título é editado manualmente, e nunca mais volta a sobrescrever naquele card.
🧩
Fan-out via automação
Ação "Aplicar fan-out" nas Automações cria todos os filhos de uma receita salva de uma vez (com Ficha Técnica do pai já mesclada), a partir de um trigger qualquer — idempotente, não duplica se o card já tem filhos.
📋
Modelos com Ficha Técnica
Modelos reutilizáveis (Toolbar → Modelos) podem salvar e aplicar a Ficha Técnica também, com merge "preenche só o que está vazio" — não sobrescreve o que já foi preenchido manualmente no card.

IA · kanban.html

Agente Ágil

Orquestrador de IA rodando como Cloud Function, com um loop de ferramentas próprio — não é mais um proxy simples pro chat da Anthropic.

💬
Gatilho: @menção em comentário
Escreva @Agente Ágil num comentário de card e a Cloud Function agenteAgilMencao (functions/agente-agil-orquestrador/mentionTrigger.js) dispara automaticamente — ouvindo o path de comentários do squad. Ignora sempre, antes de mais nada, qualquer comentário que já seja do próprio agente (evita auto-disparo em loop) e é idempotente contra reentrega do Firebase Functions.
🤖
Modo autônomo (Automações)
A ação "Notificar Agente Ágil" das Automações pode, em vez de abrir o painel local, escrever ela mesma um comentário @Agente Ágil no card que disparou a regra — entrando no mesmo pipeline validado da @menção humana, sem nenhuma Cloud Function nova. Disponível hoje no squad dev.
Ferramenta (tool_use)O que faz
ler_cardLê o resumo do card atual — descrição, checklist, comentários, coluna, tags, responsável/participantes. Chamada antes de agir em pedidos abertos.
visao_boardVisão agregada do board: WIP vs. limite por coluna, throughput, cycle/lead time, gargalo por coluna e bloqueios ativos.
biblioteca_agilBase de conhecimento estática — conceitos ágeis e como cada funcionalidade do Maré Digital funciona na prática.
mover_colunaMove o card para outra coluna.
editar_camposEdita título, descrição, tags, prioridade e outros campos do card.
checklist_itemAdiciona ou marca um item de checklist.
comentarioPosta um comentário no card.
linkAnexa um link ao card.
relatorio_htmlGera um relatório em HTML sobre o card ou o board.
agent_statusMarca o status do trabalho do agente no card (ex: awaiting_validation).
perguntar_humanoPausa a tarefa e posta uma pergunta como comentário quando o agente não sabe como prosseguir — não adivinha uma resposta.
🔑
Chave protegida via Secret Manager
A chave da Anthropic é gerenciada com defineSecret() (firebase-functions/params) e configurada via firebase functions:secrets:set — nunca fica em código, nem em variável de ambiente em texto puro.

Automações (Butler-style)

Regras "quando X → então Y" pelo PO, persistidas no Firebase (auto_rules), executadas localmente por runAutoRules(). 20 triggers, 14 ações.

⚡
Triggers
Movido para coluna · Criado · Prioridade definida · Atribuído a · Vence hoje · Atrasado · WIP excede limite · Checklist 100% · Risco adicionado · Impedido/desbloqueado · Parado há muito tempo (aging) · Tag adicionada/removida · Submarca/tamanho definidos · Marcado como OKR · Capa definida · Padrão de card definido · Modelo usado · Recorrente criado.
🎬
Ações
Mover para coluna · Definir prioridade · Adicionar/remover tag · Atribuir responsável · Notificar Agente Ágil (painel ou @menção autônoma) · Definir submarca/tamanho/demandante/padrão/capa · Marcar como OKR · Adicionar item de checklist · Aplicar fan-out (criar cards filhos).
🤖
Notificar Agente Ágil — 2 modos
Aba clássica (abre o painel local do Agente Ágil pré-preenchido) ou Modo autônomo — escreve o comentário @Agente Ágil direto no card, disparando o orquestrador via Cloud Function sem intervenção humana. Modo autônomo disponível hoje no squad dev.
🧪
AutoLab — teste antes de ativar
Botão Testar no AutoLab simula o efeito da regra no estado atual do board, mostrando quais cards seriam afetados antes de ativar de verdade.

Notificações & Push

Notificação in-app é o dado de verdade; push é uma decisão separada, tomada no servidor.

🔔
Fluxo
O app decide que algo merece notificar e escreve em usuarios/{uid}/notificacoes/{id}. A Cloud Function sendPushOnNotification só decide se também vira push — checando o type contra uma allow-list e a janela de "Não Perturbe" da pessoa (notif_prefs/dnd).
TipoVira push?
assigned · mention · unblocked · risk · recorrente · painel_broadcast · intakeSim, se fora do DND
due_today · due_overdueNão — só in-app, com deduplicação diária determinística
📵
Mensagens data-only
FCM envia só data (sem o campo notification) de propósito — os dois juntos fazem alguns browsers (Safari/iOS) mostrarem a notificação duas vezes.

Sandbox & Dev Seed

Ambiente isolado para testar features novas antes de ir para produção.

🧪
O que é o kanban-dev
Cópia funcional do kanban.html com squad padrão em dev. Dados isolados em kanban/squads/dev/ — não interferem em produção. Mesmo Firebase, mesma lógica. É também o único squad onde o "Modo autônomo" do Agente Ágil (via Automações) está ligado hoje.
🌱
Dev Seed — runDevSeed()
Se o board dev está vazio ao abrir, um overlay de seed lista os cards que serão criados. Ao confirmar, popula o board com dados fictícios realistas — cards com tags, donos, prazos, checklists e riscos. Log visual em tempo real mostra cada card criado. Ideal para demos e testes de UI.
🔁
Ciclo de desenvolvimento
Feature → testada no dev → validada explicitamente por quem pediu → portada para kanban.html cirurgicamente (nunca uma cópia cega do arquivo).
📋
Squad dev no Painel
Aparece no seletor do Painel identificado como sandbox. Backups do dev são separados dos de produção.

Segurança

Camadas de segurança

Camadas independentes. Se uma falhar, as outras continuam de pé.

✓ ativo
Escape de HTML (XSS)
esc() e safeUrl() aplicados em todos os pontos de renderização. Dados do Firebase nunca entram crus no innerHTML. Presente em kanban, kanban-dev e painel.
✓ ativo
Firebase Database Rules
Verifica auth.token.email no servidor. Campo role só alterável por PO. Associação usuário↔squad validada por .validate — checa domínio corporativo ou a whitelist de externos do próprio squad.
✓ ativo
Chave da Anthropic no Secret Manager
Gerenciada via defineSecret()/firebase functions:secrets:set. Nunca no HTML, nunca em localStorage, nunca em trânsito para o browser.
✓ ativo
RBAC + ADMs hardcoded
PO/Org/Membro com permissões distintas. ADMs via ADM_EMAILS têm papel mínimo PO — não rebaixável editando o banco.
✓ ativo
Allow-list de push
sendPushOnNotification só converte em push os tipos na allow-list PUSH_TYPES, e respeita a janela "Não Perturbe" de cada pessoa.
✓ ativo
Orquestrador com dryRun e idempotência
Escrita real no board é opt-in explícito (dryRun:false, nunca default). Gatilho por @menção ignora sempre comentários do próprio agente e protege contra reentrega de eventos.

Cloud Functions & Secrets

Duas funções deployadas em functions/, rodando com credenciais próprias do Firebase — nada de proxy externo.

FunçãoTriggerO que faz
sendPushOnNotificationonValueCreated em usuarios/{uid}/notificacoes/{id}Converte notificações elegíveis (allow-list PUSH_TYPES) em push via FCM, respeitando o DND e prunando tokens inválidos.
agenteAgilMencaoonValueCreated em card_comments do squad devDetecta @Agente Ágil num comentário e roda o loop do orquestrador contra o card, usando as ferramentas reais.
