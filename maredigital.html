Sistema Kanban desenvolvido internamente. Páginas HTML autocontidas (sem build, sem servidor próprio), sincronização em tempo real via Firebase, um orquestrador de IA rodando em Cloud Functions e suporte a múltiplos squads.

01
Visão geral

O que é o Maré Digital

Kanban ágil single-file que roda no browser. Deploy = git push no GitHub Pages.

📄
Single-file app
HTML, CSS e JS num único arquivo por tela, com <script type="module"> importando o SDK do Firebase direto do CDN. Sem build, sem npm no root, sem servidor próprio.
🔄
Tempo real
Firebase Realtime DB via WebSocket — qualquer mudança aparece no board de todos em menos de 1s. Cards, presença, notificações e comentários são todos listeners ao vivo.
🤖
Agente Ágil
Orquestrador de IA rodando em Cloud Function: lê o card, o board inteiro e a base de conhecimento ágil, e age via ferramentas (mover, comentar, editar campos, perguntar a um humano).
🔔
Push de verdade
Notificações in-app viram push (Firebase Cloud Messaging) quando o tipo está na allow-list — respeitando a janela de "Não Perturbe" de cada pessoa.
🏢
Multi-squad
Um deployment serve N squads via ?squad=id, incluindo squads criados dinamicamente pelo Painel. Dados isolados por squad no Firebase.
🔒
Acesso controlado no servidor
Login Google restrito a @ciahering.com.br (+ uma whitelist de externos por squad). Associação usuário↔squad validada nas próprias Firebase Rules, não só na UI.
02
Infraestrutura

Arquitetura

GitHub Pages para as páginas, Firebase para dados e auth, Cloud Functions para tudo que precisa de um segredo ou rodar sem o browser aberto.

📦
O que fica no Firebase
Cards, tags, colunas, sprint cfg, automações, backups, comentários, notas, notificações, logs de erro, presença. Segregado por squad — regras validam associação usuário↔squad no servidor.
🔑
O que fica na Cloud Function
A chave da Anthropic, gerenciada via firebase functions:secrets:set (Secret Manager), nunca em HTML/localStorage. Além do push e do orquestrador, há Cloud Functions pra intake anônimo, backup semanal automático e a integração com Spotify (hoje pausada) — ver seção "Cloud Functions & Secrets".

Adm
Tudo que PO faz, mais o que nenhum papel de squad cobre: registrar como 🏛 Squad Gestão, gerenciar ADM_EMAILS pelo Painel, moderar conteúdo de outros usuários (ex.: excluir um Kudos que não é seu). Papel de verdade gravado no Firebase — não é só um override de tela.
PO
Agente Ágil, configurações, gestão de papéis, convite de membros, backup, automações.
Organizador
Agente Ágil, tudo no board. Não altera papéis de outros membros.
Membro
Cria, edita e move cards. Sem Agente Ágil, sem configurações avançadas. Externo autorizado (fora de @ciahering.com.br) entra como convidado — mesma base, papel mais restrito.
🛡
ADMs — getEffectiveRole()
Dois e-mails (caio.soares e rafael.passos, extensível pelo Painel → Gestão de usuários sem editar código — ver seção 20) entram em ADM_EMAILS e ganham o papel adm de verdade, gravado no Firebase no login (isAdmUser()). A função getEffectiveRole() força esse papel toda vez independente do que já estiver salvo — não dá pra rebaixar um ADM editando o banco direto.
🔐
Associação usuário↔squad validada no servidor
Escrever true em usuarios/{uid}/squads/{squadId} só é aceito pelas Firebase Rules se o e-mail do usuário for @ciahering.com.br ou constar em squads/{squadId}/externos — não é mais uma checagem só de UI. Externos são identificados pela sua própria chave (_extKey(email)), não por um índice arbitrário.

Supercards & Ficha Técnica

Um card pai com N cards filhos, com dados técnicos compartilhados entre eles.

🧩
Cards filhos
Um card pai (childCardIds) agrupa filhos (superParentId) — útil pra desdobrar uma campanha/entrega grande em partes menores sem perder o vínculo com o todo. Ao criar um filho, dá pra buscar entre cards já existentes no board (2+ caracteres) em vez de sempre criar um novo.
📄
Ficha Técnica compartilhada
Campos técnicos definidos no pai se propagam para os filhos. Título automático do filho reflete os objetivos ainda não marcados na Ficha Técnica — mas some assim que o título é editado manualmente, e nunca mais volta a sobrescrever naquele card.
🧩
Fan-out via automação
Ação "Aplicar fan-out" nas Automações cria todos os filhos de uma receita salva de uma vez (com Ficha Técnica do pai já mesclada), a partir de um trigger qualquer — idempotente, não duplica se o card já tem filhos.
📋
Modelos com Ficha Técnica
Modelos reutilizáveis (Toolbar → Modelos) podem salvar e aplicar a Ficha Técnica também, com merge "preenche só o que está vazio" — não sobrescreve o que já foi preenchido manualmente no card.
10
IA · orquestrador

Agente Ágil

Orquestrador de IA rodando em Cloud Functions (functions/agente-agil-orquestrador/) — um loop de ferramentas de verdade contra a API da Anthropic (runLoop()/buildTools()/systemPrompt.js), não um proxy simples de chat. Substitui a geração anterior (functions/agente-agil/, v0-v3) — essa continua deployada só como o ponto de entrada HTTP que especialistas externos usam pra enfileirar informação (ver "Especialistas externos" abaixo), nunca mais decide sozinha o que fazer com um card.

4 formas de acionar o orquestrador
GatilhoComo funciona
@menção em comentárioEscreva @Agente Ágil num comentário de card — mentionTrigger.js é uma fábrica multi-squad (createMentionTrigger()): cada squad com escrita real vira sua própria Cloud Function (agenteAgilMencao pro squad dev, agenteAgilMencaoDados pro squad dados). Ignora sempre comentários do próprio agente (evita loop) e é idempotente contra reentrega do Firebase Functions.
Especialista externo (HTTPS)Um sistema fora do Maré Digital (ex.: Databricks) manda texto livre pro endpoint HTTP de agente-agil/http.js — que só valida e enfileira em agente_intake_pending, nunca aplica ação nenhuma sozinho. intakeTrigger.js processa a fila e decide o que fazer (comentar, mover, sugerir um card novo via criar_card...). Squad dev, escrita real.
Automação "Notificar Agente Ágil"Uma regra de Automação (ver seção 11) pode escrever ela mesma um comentário @Agente Ágil no card que disparou — entra no mesmo pipeline da @menção humana, sem Cloud Function extra. Também dispara sozinho 1x/dia pra "Card vence hoje"/"Card atrasado" via dueOverdueTrigger.js (scan agendado, squads dev e dados), se a regra correspondente estiver configurada naquele squad.
🤖 Resumo do Agente Ágil (Meu Dia)resumoMeuDia.js — único caminho sob demanda (onRequest, botão no painel "Meu Dia") e o único que não escreve nada no board — só lê os cards ativos da pessoa e devolve um resumo interpretado (atrasados, bloqueados, sem descrição...). Sem cards pendentes, nem chama o modelo (custo zero).

visao_boardVisão agregada do board: WIP vs. limite por coluna, throughput, cycle/lead time, gargalo por coluna e bloqueios ativos.

Além de título/descrição/prazo, aceita checklist (até 20 itens), tags (até 10, casadas por nome/label no cliente) e riscos (até 10) opcionais — todos ausentes por padrão, sempre gravados como [] quando não informados.

Quando ainda não existe um card pra vincular (gatilho de especialista externo, sem cardId resolvido), o toolset fica restrito a criar_card/visao_board/biblioteca_agil — as demais exigem um card já existente.
🔌
Contexto de especialistas externos
Registro global (kanban/config/agentesExternos/{especialista}, editado no Painel → ⚙ Config → 🔌 Agentes Externos) onde ADM/PO descreve o que cada sistema externo faz e em quais squads a descrição vale. O orquestrador injeta essa descrição no início da tarefa sempre que a mensagem vem daquele especialista naquele squad — sem precisar que o texto se auto-explique toda vez.
📜
Histórico do Agente Ágil
Aba "🤖 Histórico do Agente" em ⚙ Configurações (kanban.html) — todas as vezes que o agente mudou algo num card daquele squad, com a origem (@menção, Automação, ou especialista externo) e a lista de ações em português simples. Não polui com chamadas que só leram o card.
💬
Card "Converse com o Agente Ágil"
Card especial, fora do grafo normal (sem dono, sem prazo, fora de métricas/buscas) — pra conversa solta que não precisa virar uma tarefa de verdade. Também recebe o comentário quando um especialista externo manda algo sem card associado e nada de acionável nasce daquilo.
🧭
Roteamento de modelo + cache
escolheClienteParaTarefa.js manda perguntas curtas/conceituais pro haiku e o resto (qualquer pedido de ação) pro sonnet, com override manual disponível. Prompt caching (system + histórico) evita reprocessar do zero a cada iteração do loop.
🤖
Agentes de IA cadastrados no board
Identidades de IA (kanban/squads/{squad}/dados/agentes, cadastradas em kanban.html → ⚙ Configurações → Usuários → "🤖 Agentes de IA") — aparecem como opção de Responsável/Participante, lado a lado com pessoas. Quando o orquestrador muda algo de verdade num card com um desses agentes como responsável/participante, posta um comentário extra marcando ele (agenteMarcador.js) — como o agente não tem uid/login pra receber notificação de verdade, é o jeito de "avisar" ele que existe hoje. A ferramenta cards_por_agente consulta quais cards já são de qual agente.
🔌
Agentes Externos também viram Responsável/Participante
Mesmo registro global de "Contexto de especialistas externos" acima (kanban/config/agentesExternos) ganhou campos opcionais de init/cor/avatarEmoji — com init preenchido, o agente vira selecionável no board igual um Agente de IA decorativo, num optgroup próprio "🔌 Agentes Externos". A diferença real: agenteMarcador.js não só posta o comentário de marcação — nos squads em NOTIFICAR_ESPECIALISTA_SQUADS (hoje só dev), também chama de verdade o mesmo handler HTTP de notificar_especialista_externo, de forma determinística (não depende do modelo lembrar de chamar a ferramenta) toda vez que o card muda. O agente externo nunca age sobre o board — é só destinatário.
⚡
Automação ↔ Agente Ágil, nas duas direções
Automação → agente: a ação "Notificar Agente Ágil" (seção 11). Agente → automação: quando o orquestrador move um card, edita campos, marca um checklist ou registra um risco (escrita direta no Firebase, fora do fluxo normal do cliente), ele enfileira o evento em agente_pending_auto — qualquer board aberto reivindica a entrada via transaction() e dispara a Automação correspondente, garantindo 1 disparo só mesmo com várias pessoas com o board aberto ao mesmo tempo.
🔑
Escrita real é opt-in, chave protegida via Secret Manager
Cada squad só ganha escrita de verdade (dryRun:false) depois de validado — hoje são dev e dados. A chave da Anthropic é gerenciada com defineSecret() (firebase-functions/params) e configurada via firebase functions:secrets:set — nunca fica em código, nem em variável de ambiente em texto puro.

Automações (Butler-style)

Regras "quando X → então Y" pelo PO, persistidas no Firebase (auto_rules), executadas localmente por runAutoRules(). 21 triggers, 15 ações.

⚡
Triggers
Movido para coluna · Criado · Prioridade definida · Atribuído a · Vence hoje · Atrasado · WIP excede limite · Checklist 100% · Risco adicionado · Impedido/desbloqueado · Parado há muito tempo (aging) · Tag adicionada/removida · Submarca definida · Marcado como OKR · Capa definida · Padrão de card definido · Modelo usado · Recorrente criado · Agendado criado.
🎬
Ações
Mover para coluna · Definir prioridade · Adicionar/remover tag · Atribuir responsável · Notificar Agente Ágil (painel ou @menção autônoma) · Notificar todos (📣 @todos sintético) · Definir submarca/tamanho/demandante/padrão/capa · Marcar como OKR · Adicionar item de checklist · Aplicar fan-out (criar cards filhos).
🤖
Notificar Agente Ágil
Escreve o comentário @Agente Ágil direto no card que disparou a regra, entrando no mesmo pipeline validado da @menção humana — sem Cloud Function extra. Disponível nos squads com escrita real do orquestrador (dev e dados).
📣
Notificar todos
Posta um comentário @todos [Automação] ... no card, disparando o mesmo branch de parseMentions() que a menção coletiva usa quando digitada à mão — opts.includeSelf:true nesse caso (notifica literalmente todo mundo do squad, mesmo quem por acaso processou o disparo). Qualquer squad, não só os com Agente Ágil.
🧪
AutoLab — teste antes de ativar
Botão Testar no AutoLab simula o efeito da regra no estado atual do board, mostrando quais cards seriam afetados antes de ativar de verdade.
🔁
Também dispara pra mutações do Agente Ágil
Automações são avaliadas no cliente (runAutoRules()), mas o orquestrador escreve direto no Firebase via Admin SDK. Uma fila (agente_pending_auto) faz a ponte: o backend anuncia o que mudou, qualquer board aberto reivindica a entrada por transaction() antes de disparar a regra — garantindo 1 disparo só, não 1 por aba aberta. Ver seção "Agente Ágil" pra mais detalhe.

Notificações & Push

Notificação in-app é o dado de verdade; push é uma decisão separada, tomada no servidor.

🔔
Fluxo
O app decide que algo merece notificar e escreve em usuarios/{uid}/notificacoes/{id}. A Cloud Function sendPushOnNotification só decide se também vira push — checando o type contra uma allow-list e a janela de "Não Perturbe" da pessoa (notif_prefs/dnd).
TipoVira push?
assigned · mention · unblocked · risk · recorrente · painel_broadcast · intakeSim, se fora do DND
due_today · due_overdueNão — só in-app, com deduplicação diária determinística
📵
Mensagens data-only
FCM envia só data (sem o campo notification) de propósito — os dois juntos fazem alguns browsers (Safari/iOS) mostrarem a notificação duas vezes.

Segurança

Camadas de segurança

Camadas independentes. Se uma falhar, as outras continuam de pé.

✓ ativo
Escape de HTML (XSS)
esc() e safeUrl() aplicados em todos os pontos de renderização. Dados do Firebase nunca entram crus no innerHTML. Presente em kanban, kanban-dev e painel.
✓ ativo
Firebase Database Rules
Verifica auth.token.email no servidor. Campo role só alterável por PO/Adm. Associação usuário↔squad validada por .validate — checa domínio corporativo ou a whitelist de externos do próprio squad.
✓ ativo
Chave da Anthropic no Secret Manager
Gerenciada via defineSecret()/firebase functions:secrets:set. Nunca no HTML, nunca em localStorage, nunca em trânsito para o browser.
✓ ativo
RBAC + ADMs
Adm/PO/Organizador/Membro/Convidado com permissões distintas. ADMs via ADM_EMAILS ganham o papel adm de verdade — não rebaixável editando o banco.
✓ ativo
Allow-list de push
sendPushOnNotification só converte em push os tipos na allow-list PUSH_TYPES, e respeita a janela "Não Perturbe" de cada pessoa.
✓ ativo
Orquestrador com dryRun e idempotência
Escrita real no board é opt-in explícito (dryRun:false, nunca default). Gatilho por @menção ignora sempre comentários do próprio agente e protege contra reentrega de eventos.
